# پلتفرم خرید و فروش سهام (بورس ایران) — نسخه استارتر

این پروژه یک زیرساخت کامل و واقعی برای یک پلتفرم معاملاتی است: ثبت‌نام و ورود، کیف پول،
تابلوی بازار، دفتر سفارشات (Order Book)، موتور تطبیق سفارش، پرتفوی و تاریخچه معاملات.

## ⚠️ قبل از هر چیز: چرا این به‌تنهایی «واقعی» نیست

برای اینکه کاربران واقعاً بتوانند سهام واقعی بورس تهران را با پول واقعی بخرند و بفروشند،
قانوناً باید هر سفارش از طریق یک **کارگزاری دارای مجوز سازمان بورس و اوراق بهادار** به
سامانه معاملاتی رسمی (TSETMC) ارسال شود. هیچ شخص یا شرکتی بدون مجوز کارگزاری نمی‌تواند
مستقیماً به هسته معاملاتی بورس وصل شود. به‌طور خلاصه، برای واقعی‌شدن این پلتفرم باید:

1. **قرارداد با یک کارگزاری** (مثل آگاه، مفید، فارابی و غیره) ببندید و دسترسی API/OMS
   بگیرید — این یک قرارداد B2B است، نه یک API عمومی.
2. **احراز هویت مشتری (KYC/AML)** واقعی پیاده‌سازی کنید: تطبیق کد ملی با ثبت‌احوال،
   احراز صحت شماره موبایل و حساب بانکی به نام خود شخص.
3. به یک **درگاه پرداخت مجاز** (زرین‌پال، آی‌دی‌پی و مشابه) وصل شوید تا واریز/برداشت واقعی
   انجام شود.
4. مجوزهای لازم از **سازمان بورس و اوراق بهادار** و در صورت نیاز **بانک مرکزی** را بگیرید،
   چون ارائه خدمات معاملاتی مالی به‌طور مستقل فعالیت تنظیم‌شده (Regulated) محسوب می‌شود.

این پروژه طوری طراحی شده که این کار را برایتان آسان می‌کند: تمام منطق برنامه (UI، کیف پول،
پرتفوی، دفتر سفارشات) آماده است و فقط یک فایل — `backend/broker.js` — باید به API کارگزاری
واقعی وصل شود. تا آن زمان، پلتفرم در **حالت DEMO** اجرا می‌شود: سفارش‌ها فقط داخل خود برنامه
با هم تطبیق داده می‌شوند و هیچ پول یا سهام واقعی جابه‌جا نمی‌شود.

## ساختار پروژه

```
backend/     API با Node.js + Express + SQLite
  server.js          نقطه ورود سرور
  db.js              اسکیمای دیتابیس
  matchingEngine.js  موتور تطبیق سفارش (حالت دمو)
  broker.js          نقطه اتصال به کارگزاری واقعی (باید تکمیل شود)
  routes/            auth, market, orders, wallet, portfolio
  seed.js            چند نماد نمونه برای تست

frontend/    React + Vite
  src/pages/         بازار، جزئیات نماد، ورود/ثبت‌نام، پرتفوی، کیف پول
  src/components/    Navbar, OrderBook, OrderForm
```

## راه‌اندازی (روی سیستم خودتان)

نکته: من این کد را روی محیط ابری بدون دسترسی اینترنت نوشتم، پس نصب پکیج‌ها و اجرا را باید
خودتان روی سیستم خودتان انجام دهید (که Node.js و npm نصب دارد).

### ۱. بک‌اند

```bash
cd backend
npm install
cp .env.example .env
# داخل .env مقدار JWT_SECRET را با یک رشته تصادفی طولانی جایگزین کنید
npm run seed     # چند نماد نمونه اضافه می‌کند
npm start        # روی http://localhost:4000 بالا می‌آید
```

### ۲. فرانت‌اند

```bash
cd frontend
npm install
npm run dev       # روی http://localhost:5173 بالا می‌آید
```

مرورگر را روی `http://localhost:5173` باز کنید، ثبت‌نام کنید، از صفحه «کیف پول» یک واریز
نمایشی انجام دهید، و از تابلوی بازار روی یک نماد بزنید تا سفارش ثبت کنید.

## وضعیت فعلی (حالت DEMO)

- سفارش خرید/فروش بین کاربران مختلف *داخل همین برنامه* تطبیق داده می‌شود.
- واریز کیف پول از دکمه «واریز نمایشی» است، نه پرداخت بانکی واقعی.
- هیچ احراز هویتی با ثبت‌احوال یا سامانه بورس انجام نمی‌شود؛ فیلد `kyc_status` فقط برای
  نمایش جریان کار (Flow) واقعی است.

## مسیر تبدیل به پلتفرم واقعی

1. با یک کارگزاری دارای مجوز صحبت کنید و دسترسی API بگیرید.
2. توابع `placeLiveOrder` و `cancelLiveOrder` در `backend/broker.js` را با فراخوانی واقعی
   API آن کارگزاری پر کنید.
3. `BROKER_MODE=live` را در `.env` تنظیم کنید.
4. `routes/wallet.js` را به یک درگاه پرداخت واقعی وصل کنید (به‌جای `demo-deposit`).
5. یک فرایند KYC واقعی (آپلود مدارک، تطبیق کد ملی، تایید کارگزاری) اضافه کنید که وضعیت
   `kyc_status` کاربر را به `verified` تغییر دهد.
6. الزامات امنیتی و انطباق (Compliance) لازم برای یک سرویس مالی — رمزنگاری داده حساس،
   لاگ‌گیری برای ممیزی، محدودیت نرخ درخواست، و غیره — را قبل از انتشار عمومی اضافه کنید.

هیچ‌کدام از این مراحل صرفاً فنی نیستند؛ مرحله ۱ و ۵ نیازمند مذاکره و انطباق حقوقی با یک
نهاد دارای مجوز است، نه فقط نوشتن کد.
